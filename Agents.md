# Alioth AERA bring-up rules

Use the Android 16 AERA manifest and twrp_alioth-bp2a-user target.
Build only in the separate AERA checkout. Preserve imported authorship.
Read README.md and AERA_COMPATIBILITY.md for scope and current source audit.
Alioth is recovery-as-boot; do not distribute placeholder vendor_boot images.
Historical PBRP patch/runtime records are provenance, not AERA acceptance.
Never disable Android policy checks to obtain a build. Do not flash without
explicit scoped authorization. Keep build and runtime evidence separate.
